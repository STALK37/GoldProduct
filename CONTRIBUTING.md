# Contributing

Thanks for taking a look. Issues and pull requests are both welcome.

## Getting set up

```bash
npm install
cp .env.example .env
npm run dev
```

The site renders without a backend. Anything touching the catalogue, cart or admin panel needs a
Supabase project — [SETUP.md](SETUP.md) walks through it.

## Before opening a pull request

```bash
npm run lint         # must be clean, not just error-free
npm run typecheck
npm test
npm run test:rls     # needs PostgreSQL server binaries on the machine
npm run test:e2e     # needs `npx playwright install chromium` once
```

CI runs all five. The RLS tests need no Supabase project — they spin up a throwaway PostgreSQL.

## House rules

**Touching a policy means touching the tests.** Every RLS change needs a matching assertion in
`supabase/tests/rls.sql`. A policy that silently opens a table is the failure mode this project
cares most about; see [SECURITY.md](SECURITY.md).

**Prices are decided by the database.** If you find yourself sending a price, a total or an amount
from the browser, stop — that is the bug `place_order()` exists to prevent, and
`src/test/CheckoutDialog.test.tsx` will fail.

**Migrations are append-only.** Never edit a migration that has been applied. Add a new one; the
filename is `YYYYMMDDHHMMSS_short_description.sql`.

**Keep `src/components/ui/` as shadcn generates it.** Those files are regenerated by
`npx shadcn@latest add <component>`, and local edits get lost. Wrap them instead.

**Ukrainian is the interface language.** New user-facing copy goes in Ukrainian; comments and commit
messages in English.

## Commit messages

Short imperative subject, why in the body if it isn't obvious:

```
Move order creation into a SECURITY DEFINER function

The checkout needed SELECT on customers and orders to read back the new
row's id, which meant the anon key could read every customer record.
place_order() returns the id directly, so both tables can deny reads.
```
